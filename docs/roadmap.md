# TouchDeck 다음에 할 것

2026-10-20 기준. 화면 보기 1~3차와 Tailscale 원격까지 끝낸 뒤, 써 보면서 보인 것과 코드를 다시 읽으며 찾은 것을 모았다. 지금 당장 고칠 문제는 없다. 다시 손댈 때 위에서부터 하나씩 고르면 된다.

각 항목은 이렇게 적었다.

- **왜:** 이걸 하면 무엇이 나아지는지
- **무엇을:** 바꿀 곳
- **크기:** 작음(한두 시간), 중간(반나절), 큼(하루 이상, 설계 문서부터)
- **확인:** 다 됐는지 무엇으로 보는지

---

## 1순위: 원격을 켜 두고 다닐 때 안전하게

원격과 잠자기 막기가 생기면서, 맥이 깨어 있고 잠기지 않은 채 밖에서 붙을 수 있게 됐다. 편한 만큼 깜빡했을 때의 대가도 커졌다.

### 1-1. 잠자기 막기 자동 해제

- **왜:** 켜 둔 걸 잊으면 맥이 계속 잠들지도 잠기지도 않는다. 맥 앞의 누구나 맥을 쓸 수 있는 상태가 며칠씩 이어질 수 있다.
- **무엇을:** 맥 메뉴의 "잠자기 막기" 옆에 시간을 고르게 한다(예: 4시간, 8시간, 계속). 시간이 지나면 체크를 끄고 요청을 푼다. 남은 시간은 메뉴에 작게 보인다. 판단(언제 풀지)은 `KeepAwake`에 두고 테스트한다.
- **크기:** 작음
- **확인:** 시간이 지난 뒤 `pmset -g assertions`에서 "TouchDeck 잠자기 막기"가 사라진다.

### 1-2. 원격으로 붙으면 맥에 알리기

- **왜:** 지금은 누가 맥 화면을 보면 메뉴바 아이콘이 눈으로 바뀌는 게 전부다. 밖에서 붙은 건지 집에서 붙은 건지도 맥에서는 알 수 없다. 내 기기라도 허락받은 기기를 잃어버렸을 때 알아챌 방법이 있어야 한다.
- **무엇을:** 아이패드가 인사(`hello`)에 "원격으로 붙었음"을 싣는다. 맥은 원격 기기가 허락을 받으면 macOS 알림을 띄우고, 메뉴의 연결 목록 기기 이름 옆에 "원격"을 붙인다.
- **크기:** 작음
- **확인:** LTE와 Tailscale로 붙으면 맥에 알림이 뜬다. 집에서 붙을 때는 안 뜬다.

### 1-3. 화면 보기 중 맥에 테두리 표시와 무조작 자동 끊기

- **왜:** 원격으로 화면을 보는 걸 맥 앞에서는 놓치기 쉽다. 그리고 아이폰을 주머니에 넣은 채 보기 화면이 열려 있으면 화면과 소리가 계속 나간다.
- **무엇을:** 보는 동안 맥 화면 가장자리에 얇은 색 테두리를 띄운다(클릭을 막지 않는 창). 아이패드가 화면 보기를 연 채 백그라운드로 가거나 일정 시간(예: 10분) 아무 조작이 없으면 보기를 끝낸다.
- **크기:** 중간
- **확인:** 보는 동안 테두리가 보이고, 끝나면 사라진다. 아이폰을 잠그면 맥의 눈 아이콘이 돌아온다.

## 2순위: 테스트가 못 닿는 곳 줄이기

### 2-1. 아이패드 연결 순서를 DeckKit으로 떼어 테스트하기

- **왜:** `DeckClient`는 찾기, 원격 전환, 10초 제한, 집에서 먼저 허락받기, 재연결을 한 클래스 안에서 상태 값 여러 개로 다룬다. 원격 차수의 리뷰에서 고친 세 가지(10초 제한, 중첩 버튼, 지켜보기 쌓임)는 테스트 자리가 없어서 빌드로만 확인했다. 다음에 연결 쪽을 고칠 때 깨져도 알 방법이 없다.
- **무엇을:** "지금 상태 + 일어난 일 → 다음 상태 + 할 일"을 계산하는 순수 함수(`ConnectionMachine`)를 DeckKit에 만든다. 일어난 일은 Bonjour 찾음, 3초 지남, 연결 준비됨, 실패, 허락됨, 허락 필요 같은 것이다. `DeckClient`는 네트워크 콜백을 이 일로 바꿔 넣고, 나온 할 일(붙기, 끊기, 다시 찾기)만 실행한다.
- **크기:** 큼 (설계 문서부터)
- **확인:** 원격 실패 후 2초 뒤 다시 찾기, 원격 중 Bonjour 무시, 허락 안 된 기기의 원격 재시도 멈춤이 테스트로 박힌다. 실기기에서 집과 밖 연결이 지금과 똑같다.

### 2-2. GitHub Actions로 DeckKit 테스트 돌리기

- **왜:** 지금은 테스트를 이 맥에서만 돌린다. push할 때마다 자동으로 돌면 깜빡하고 깨진 채 올리는 일이 없다.
- **무엇을:** `.github/workflows/deckkit.yml`에서 macOS 러너로 `swift test`를 돌린다. 앱 빌드는 서명이 필요해서 빼고 DeckKit만.
- **크기:** 작음
- **확인:** GitHub PR과 push에 초록 체크가 붙는다.

## 3순위: 원격 화면을 더 낫게

### 3-1. 맥 쪽 소리 버리는 기준도 원격에 맞추기

- **왜:** 아이패드 쪽 쌓아 두는 양은 원격에서 0.2초로 늘렸다. 맥은 아직 보내는 중인 소리 묶음이 10개(약 0.2초) 밀리면 버린다. LTE에서 더 길게 막히면 아이패드가 기다려 줘도 맥에서 이미 버린 소리는 못 듣는다.
- **무엇을:** 아이패드가 `startScreen`에 원격인지 알린다(1-2와 같은 칸을 써도 된다). 맥은 원격이면 소리 한도를 30개(약 0.6초)로 둔다.
- **크기:** 작음
- **확인:** 지금 LTE 소리가 괜찮으니 급하지 않다. 끊김이 다시 들리면 이것부터 한다.

### 3-2. HEVC로 바꿔 같은 양에 더 또렷하게

- **왜:** 원격은 4Mbps 상한이라 글자가 많은 화면에서 흐려질 수 있다. HEVC(H.265)는 H.264보다 같은 화질을 더 적은 양으로 보낸다. 아이패드와 맥 모두 하드웨어로 푼다.
- **무엇을:** 맥 압축기를 `kCMVideoCodecType_HEVC`로 만들고, 영상 묶음의 첫 정보(파라미터 세트)를 HEVC 모양(VPS, SPS, PPS)으로 보낸다. 아이패드는 그걸로 형식 정보를 만든다. 예전 앱과 섞일 수 있으니 기능 번호를 3으로 올리고, 둘 다 3일 때만 HEVC.
- **크기:** 중간
- **확인:** 원격에서 같은 4Mbps로 터미널 글자가 H.264보다 또렷하다(같은 화면 두 장 비교).

### 3-3. 원격 재연결 빠르게

- **왜:** 원격이 끊기면 2초 쉬고, 다시 Bonjour로 3초 찾은 뒤에야 주소로 간다. 밖에서는 매번 5초쯤 걸린다.
- **무엇을:** 마지막 연결이 원격이었으면, 다시 찾을 때 Bonjour와 주소를 같이 시작해서 먼저 되는 쪽을 쓴다. 집에 돌아온 경우를 위해 Bonjour가 이기면 Bonjour로 간다.
- **크기:** 중간 (2-1을 먼저 하면 작음)
- **확인:** 밖에서 연결이 끊긴 뒤 다시 붙기까지 걸린 시간이 줄어든다(로그 시각으로 잰다).

### 3-4. 지연 시간 표시

- **왜:** 화면이 늦게 따라올 때 네트워크 탓인지 맥 탓인지 모른다.
- **무엇을:** 보기 화면에서 몇 초마다 작은 확인 메시지를 주고받아 왕복 시간을 재고, 툴바 구석에 "80ms"처럼 보인다. 너무 늘면 색을 바꾼다.
- **크기:** 작음
- **확인:** 집 와이파이와 LTE에서 숫자가 다르게 나온다.

### 3-5. 화질 자동 조절

- **왜:** 지금 원격 화질은 고정값이다. LTE가 좋을 때는 더 또렷하게, 나쁠 때는 더 낮게 갈 수 있다.
- **무엇을:** 맥이 `SendGate`에서 프레임을 버린 횟수를 몇 초 단위로 세서, 많으면 비트레이트를 내리고 한동안 없으면 상한까지 천천히 올린다. 판단은 DeckKit에서 테스트한다.
- **크기:** 중간
- **확인:** LTE에서 화면이 멈추는 일이 줄고, 와이파이에서는 상한까지 올라간다.

## 4순위: 보안 남은 것

### 4-1. 맥에 저장한 기기 토큰을 키체인으로

- **왜:** 허락한 기기의 토큰이 맥 설정 파일(`config.json`)에 그대로 들어 있다. 아이패드는 이미 키체인에 둔다. 이 파일을 누가 복사하면 그 기기 행세를 할 수 있다.
- **무엇을:** 토큰은 키체인에 기기 ID로 저장하고, 설정 파일에는 ID와 이름만 남긴다. 앱이 처음 켜질 때 예전 파일의 토큰을 키체인으로 옮긴다.
- **크기:** 작음
- **확인:** `config.json`에 토큰이 없고, 허락한 기기는 다시 허락받지 않고 붙는다.

### 4-2. QR로 처음 허락받기

- **왜:** 처음 짝지을 때 누가 중간에 끼면 4자리 숫자를 오프라인으로 맞혀 볼 수 있다(5편 남는 한계). 지금은 집 와이파이에서만 짝짓게 해서 위험이 낮지만, 남은 한계 중 가장 크다.
- **무엇을:** 맥 메뉴에 QR을 띄우고, 아이패드 카메라로 찍어 맥 공개 키를 직접 확인한다. 숫자 입력은 카메라를 못 쓸 때만 남긴다.
- **크기:** 중간
- **확인:** 가짜 맥(다른 공개 키)으로는 QR 확인에서 걸린다.

## 시험 중: 아이폰 Face ID로 맥 잠금 풀기

- **왜:** 맥 앞에 앉을 때 비밀번호 대신 아이폰 Face ID로 화면 잠금을 푼다. 애플워치 잠금 해제와 비슷한 것.
- **될지 먼저 볼 것:** macOS에는 다른 앱이 잠금을 푸는 공식 기능이 없다. 맥 앱이 잠금 화면 비밀번호 칸에 키를 대신 쳐 주는 방법뿐이고, 잠금 화면이 앱이 보낸 키 입력을 받는지는 시험해야 안다(브랜치 `spike/lock-screen-typing`). 켤 때의 첫 로그인 화면(FileVault)은 어떤 방법으로도 안 된다.
- **시험이 되면 할 것 (설계 문서부터):**
  1. 맥 비밀번호는 아이폰 키체인에만, Face ID를 통과해야 꺼낼 수 있는 칸에 둔다. 맥에는 저장하지 않는다.
  2. 가까이 있을 때만. 맥이 연결 상대 주소를 보고 Tailscale 주소(100.64.0.0/10, fd7a:115c:a1e0::/48)면 거절한다. 같은 와이파이와 기기끼리 직접 연결만 받는다. 아이폰도 원격이면 버튼을 숨긴다.
  3. 치기 직전에 정말 잠금 화면인지 다시 확인한다. 아니면 아무것도 치지 않는다(앞에 떠 있는 앱에 비밀번호가 들어가는 것을 막는다).
  4. 봉투 안에서만 오가고 로그에 남기지 않는다. 기기마다 맥 메뉴에서 따로 켠다(기본 꺼짐). 실패하면 잠깐 막고, 풀면 맥에 알림을 띄운다.
- **대가:** 맥 비밀번호를 바꾸면 아이폰에서도 다시 넣어야 한다. 맥 잠금이 아이폰 Face ID만큼의 보안이 된다.
- **크기:** 중간 (시험 결과에 달림)

## 5순위: 스트림덱 기능

- **단축키 버튼:** ⌘⇧4 같은 단축키를 버튼에 담는다. 화면 보기의 특수 키를 만든 코드(`RemoteKey`, `CGEvent`)를 그대로 쓴다. 작음.
- **매크로:** 여러 동작(앱 열기, 0.5초 쉬기, 단축키)을 한 버튼에 이어 붙인다. 중간.
- **앞에 있는 앱 따라 페이지 바꾸기:** Xcode가 앞이면 Xcode 페이지로. 맥이 앞에 있는 앱이 바뀔 때 알린다. 중간.
- **버튼 색과 아이콘 고르기:** SF Symbols나 색을 직접 고른다. 작음.
- **배치 내보내기와 백업:** 배치를 파일로 내보내고 다시 불러온다. 작음.

## 보드가 오면

- **ESP32 CYD:** 보드 쪽 C++와 맥 연결. 처음 구상대로 보드와 맥은 BLE로 시작한다. 아이콘을 8KB씩 쪼개 보내고 이어받기, 속도 조절이 글감이다. 보드는 Tailscale을 못 쓰니 원격은 해당 없다. 큼.

## 하지 않기로 한 것

- **클립보드 주고받기:** 유니버설 클립보드로 충분하다.
- **아이패드와 맥 사이를 BLE로 바꾸기:** 와이파이와 직접 연결로 충분하다. BLE는 보드에만 쓴다.
- **공유기 포트 열기, 중계 서버:** Tailscale로 해결했다.
- **소리 압축:** 1.5Mbps라 아낄 양이 작고, LTE 끊김은 쌓아 두는 양으로 풀렸다.

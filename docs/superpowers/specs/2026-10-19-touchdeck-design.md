# TouchDeck 설계: 아이패드/아이폰 스트림덱 (ESP32 전 단계)

> 2026-10-19 해롤드와 대화로 정리. 원래 구상은 `~/Downloads/Project/아이폰_맥_컨트롤_프로젝트_가이드.md`(2026-10-08)에 있다. 이 문서는 그 가이드의 1~2단계를 아이패드 중심으로 다시 정한 것이다.

---

## 1. 무엇을, 왜

해롤드는 나중에 ESP32 터치 보드(CYD 2.8")로 "나만의 스트림덱"을 만들 계획이다. 보드를 사기 전에 **아이패드를 스트림덱으로** 먼저 쓴다. 아이패드는 지금 책상 위, 모니터 바로 옆에 있다. 손을 뻗어 버튼을 탭하면 맥북에서 앱이 열리거나 명령이 실행된다.

이 단계에서 맥과 아이패드/아이폰 쪽을 완성해 두면, 보드가 왔을 때 보드는 같은 방식으로 맥에 붙기만 하면 된다. 그때 아이폰/아이패드는 보드 버튼을 꾸미는 설정판 역할도 맡는다.

만드는 과정은 블로그 시리즈로 쓴다. 블로그 주제가 되는 것 자체가 이 프로젝트의 이유 중 하나다.

**성공 기준:** 해롤드가 매일 아이패드 버튼으로 Xcode/Safari 같은 앱을 열고, `blogrun` 같은 별칭 명령을 실행하고, 소리 크기를 조절한다.

## 2. 목표 / 하지 않을 것 / 실패로 보는 것

### 목표
- 아이패드(가로) 화면의 버튼을 탭하면 맥에서 실행된다
- 버튼 종류 세 가지
  - **앱 실행**: 맥에 설치된 앱을 연다
  - **명령어 실행**: Alacritty 새 창을 열고 그 안에서 명령을 실행한다 (`blogrun`, `postblog`, `uploadimg` 같은 zsh 별칭 포함)
  - **새 Alacritty 창**: 빈 Alacritty 창을 하나 더 연다 (`alacritty &`와 같은 효과)
- 맥 소리 크기 조절 (화면 오른쪽 세로 슬라이더)
- 버튼 추가/편집은 아이패드(아이폰)에서: 빈 칸 탭 = 추가, 버튼 길게 누르기 = 편집
- 페이지 넘기기 (한 페이지 12칸)
- 아이폰에서도 같은 앱이 돈다
- 처음 연결하는 기기는 맥에 뜬 4자리 숫자로 허락받아야 붙는다

### 하지 않을 것 (이번 단계)
- ESP32 보드 코드, 보드용 RGB565 아이콘 변환 (보드 산 뒤에)
- 블루투스(BLE) 연결
- 단축어 / 웹 주소 / 폴더 열기 같은 다른 버튼 종류 (가이드 5단계, 나중에)
- 버튼 끌어서 순서 바꾸기
- 맥 메뉴바 앱 안의 편집 화면
- 맥 여러 대 동시 연결, iCloud 동기화
- 맥 로그인 시 자동 실행(SMAppService)
- 앱스토어 배포, 서명 설정 (해롤드가 나중에 빌드할 때 직접 한다)
- `fixaudio` (sudo 명령. 요즘 문제 없어서 뺐다)

### 실패로 보는 것
- 같은 와이파이의 아무나 해롤드 맥에 명령을 실행시킬 수 있는 상태
- 명령 버튼이 "실행됨"이라고 하는데 실제로는 별칭을 못 찾거나 엉뚱한 폴더에서 돌아 실패하는 것
- 아이패드 화면이 스크롤되는 것 (화면 전체는 고정, 페이지는 옆으로 넘기기만)
- 진행 상황을 근거 없이 꾸며 보여주는 것 (가짜 진행률 등)

## 3. 정해진 것

### 기기와 버전
- 아이폰 iOS 27, 아이패드 iPadOS 26.7.1, 맥 macOS 27.0.1, Xcode 27.0
- 최소 버전: **iOS/iPadOS 26, macOS 26** (해롤드 기기 기준. WWDC25 Network 프레임워크 새 API를 쓸 수 있다)
- 해롤드 메인 터미널은 **Alacritty** (`/Applications/Alacritty.app`)

### 구조 (가이드 문서에서 정한 원칙 그대로)
```
아이패드/아이폰 앱  ◀── 와이파이 WebSocket ──▶  맥 메뉴바 앱 ──▶ 앱 실행 / Alacritty / 볼륨
 (버튼판 + 설정판)                              (서버 + 설정 원본 JSON)
                                                    ▲
  나중에: ESP32 보드 ◀──── 같은 WebSocket ─────────┘
```
- **설정 원본은 맥에만** 둔다. 아이패드/아이폰은 받아서 보여주고, 고칠 땐 맥에 요청한다. 맥이 바뀐 배치를 붙어 있는 모든 기기에 다시 보낸다.
- 아이패드와 맥은 계속 붙어 있어야 해서 블루투스가 아니라 **와이파이 + WebSocket**. 나중에 ESP32도 이 방식으로 붙는다 (MultipeerConnectivity는 ESP32가 못 알아들어서 안 쓴다).
- 아이패드는 맥을 **Bonjour**로 자동으로 찾는다. IP 입력 없음. 서비스 이름 `_touchdeck._tcp`.
- 맥 서버는 **애플 Network 프레임워크** (`NWListener` + WebSocket 프로토콜 옵션). 외부 라이브러리 없음. 같은 `NWListener`가 Bonjour 광고도 한다. 가이드는 Hummingbird였지만, 해롤드가 ChatBird를 제대로 써 본 게 아니라서 익숙함의 이점이 없고, 아이패드도 같은 프레임워크(`NWBrowser` 등)로 맥을 찾으니 하나만 배우면 된다. 해롤드가 추천을 요청해서 Claude가 고른 것 (2026-10-19)

### 아이패드 화면 (해롤드가 고른 B안)
```
┌──────────────────────────────────────────┐
│ [Xcode] [Safari] [Finder] [음악]    │ 🔊 │
│ [새 터미널][blogrun][postblog][uploadimg]│  █ │
│ [메모]  [캘린더]  [ + ]   [ + ]     │  █ │
│              ● ○ ○                  │ 55 │
└──────────────────────────────────────────┘
```
- 가로 방향. 버튼 4열×3줄 = 12칸, 오른쪽 끝에 세로 볼륨 슬라이더가 항상 붙어 있다
- 버튼 격자를 옆으로 밀면 다음 페이지. 아래에 페이지 점. 볼륨 슬라이더는 페이지와 무관하게 고정
- 빈 칸은 `+`로 보이고, 탭하면 추가 화면
- 버튼을 길게 누르면 편집 화면 (아이폰 홈 화면 편집과 비슷한 느낌)
- 앱 버튼은 맥에서 받은 실제 앱 아이콘을 보여준다. 명령어 / 새 터미널 버튼은 구분되는 모양으로 (목업에서는 색으로 구분했다: 앱=파랑, 명령어=초록, 새 터미널=주황, 볼륨=보라)
- 맥에 연결이 안 됐을 때는 그 상태가 분명히 보여야 한다

### 편집 화면
- 종류 선택: 앱 / 명령어 / 새 Alacritty 창
- **앱**: 맥에 설치된 앱 목록이 아이콘과 함께 뜨고, 하나 고른다 (검색 있으면 좋다)
- **명령어**: 버튼 이름, 명령 글자(예: `blogrun`), 실행할 폴더(선택, 예: `~/Documents/Workspace/blog`)
  - 폴더가 필요한 이유: `blogrun`은 `bundle exec jekyll serve`라서 블로그 폴더 안에서 돌아야 한다
- **새 Alacritty 창**: 버튼 이름만 (선택으로 시작 폴더)
- 저장 / 삭제. 저장하면 맥에 보내고, 맥이 다시 보낸 배치로 화면이 바뀐다

### 맥 쪽 동작
| 버튼 종류 | 맥이 하는 일 |
|---|---|
| 앱 | 고유 ID(bundle id)로 앱 위치를 찾아 연다 (`NSWorkspace.urlForApplication(withBundleIdentifier:)` + `openApplication(at:configuration:)`) |
| 명령어 | Alacritty **새 창**을 열고, 그 안에서 zsh를 평소처럼(대화형, `~/.zshrc` 읽음) 띄워 명령을 실행한다. 명령이 끝나도 창은 남아 있고 셸을 계속 쓸 수 있다. 끄고 싶으면 그 창에서 Ctrl+C |
| 새 Alacritty 창 | `open -na Alacritty`와 같은 효과. 이미 켜져 있어도 새 창이 생겨야 한다 (그냥 앱 실행으로는 기존 창만 앞으로 온다) |
| 볼륨 | 맥 출력 소리 크기를 0~100으로 설정. 현재 값을 아이패드에 알려준다 |

- 설치된 앱 목록: `/Applications`, `/System/Applications`, `/System/Applications/Utilities`, `~/Applications`에서 `.app`을 찾는다. 이름, bundle id, 아이콘(PNG)
- 설정 파일: `~/Library/Application Support/TouchDeck/config.json`
- 메뉴바 앱(`MenuBarExtra`, Dock 아이콘 없음). 메뉴에는 연결된 기기, 페어링 숫자(요청이 있을 때), 서버 상태, 종료 정도만
- 샌드박스 끔 (개인용. Alacritty 실행과 볼륨 조절에 필요)
- 아이패드에는 실행 결과를 "실행했음 / 실패(이유)" 정도로 짧게 알려준다. 명령의 출력 자체는 맥 Alacritty 창에서 본다

### 연결 허락 (페어링)
- 처음 연결하는 기기는 맥 메뉴바에 4자리 숫자가 뜨고, 아이패드에 그 숫자를 입력해야 붙는다
- 한 번 허락한 기기는 다음부터 바로 붙는다 (기기가 토큰을 기억, 맥은 허락한 기기 목록을 기억)
- 허락받지 않은 연결은 버튼 누르기, 설정 바꾸기, 앱 목록 요청 전부 거절

### 아이폰
- 같은 앱(유니버설). 화면이 작으니 격자 배치만 화면에 맞게 바뀐다. 한 페이지 12칸이라는 데이터는 같다 (내 판단, 해롤드가 반대하지 않음)

### 블로그
- 위치: `~/Documents/Workspace/blog/_posts/StreamDeck/`, 카테고리 `[StreamDeck]`, Gesture 시리즈와 같은 형식 (front matter: title, writer: Harold, date, categories, tags, toc, toc_sticky, published)
- 첫 글 앞부분에 "클로드 코드와 바이브 코딩으로 진행한 과정"이라는 성격을 밝힌다
- 만드는 단계마다 한 편. 예상 구성 (진행하면서 바뀔 수 있음)
  1. 아이패드에서 누르면 맥에 찍히기 (Network 프레임워크 WebSocket, Bonjour, 로컬 네트워크 권한)

  4. 길게 눌러 편집, 페이지 넘기기
  5. 연결 허락 숫자
- **자세하게.** 해롤드 본인도 다시 읽는 글이다. 막힌 오류는 실제 에러 메시지, 원인, 해결까지. 낯선 개념은 코드보다 먼저 "무슨 일을 하는지" 풀어서 설명하고, 근거가 되는 애플 공식 문서 / WWDC 영상 / 라이브러리 문서 링크를 문장 가까이에 붙인다. 글 끝에 참고자료 목록

- 직접 눌러 봐야 이해되는 흐름은 인터랙티브 시뮬레이터를 만든다. 실제 코드를 보여주고 지금 도는 줄을 강조하는 방식 (RunWay 시리즈와 같은 방식)

- Xcode, 서명 같은 개발 환경 문제는 글에 쓰지 않는다. 앱 자체에서 난 오류만
- 블로그 저장소는 해롤드가 말하기 전엔 커밋/푸시하지 않는다
- 기존 블로그 규칙(메모리에 있는 헤더 형식, `---` 구분선, 생략 표기, 다음 글 예고 금지, em dash 금지 등)을 그대로 따른다

## 4. 맥 ↔ 기기 메시지 (출발점)

가이드 문서의 메시지를 바탕으로 한 출발점이다. 이름과 세부 필드는 만드는 쪽이 정리해도 된다. 단, **나중에 ESP32가 같은 메시지로 붙을 수 있게** 단순한 JSON 텍스트 메시지로 유지한다.

```jsonc
// 기기 → 맥
{ "type": "hello", "deviceId": "…", "deviceName": "Harold의 iPad", "token": "…(있으면)" }
{ "type": "pair", "code": "4821" }
{ "type": "press", "page": 0, "index": 3 }
{ "type": "getApps" }
{ "type": "setButton", "page": 0, "index": 3, "button": { "label": "blogrun", "action": { "kind": "command", "command": "blogrun", "directory": "~/Documents/Workspace/blog" } } }
{ "type": "clearButton", "page": 0, "index": 3 }
{ "type": "setVolume", "value": 55 }

// 맥 → 기기
{ "type": "needPairing" }
{ "type": "paired", "token": "…" }
{ "type": "layout", "pages": [ { "buttons": [ /* 12칸, 빈 칸은 null */ ] } ] }
{ "type": "apps", "items": [ { "name": "Xcode", "bundleId": "com.apple.dt.Xcode", "icon": "<base64 PNG>" } ] }
{ "type": "pressResult", "page": 0, "index": 3, "ok": true, "message": null }
{ "type": "volume", "value": 55, "muted": false }
```
- `action.kind`: `"app"`(bundleId) / `"command"`(command, directory?) / `"terminal"`(directory?)
- 앱 버튼의 아이콘은 `layout`에 직접 넣지 말고 bundle id로 참조. 기기가 아이콘을 따로 받아 기억해 둔다 (나중에 보드에서도 같은 생각으로 아이콘을 한 번만 받는다)

## 6. 만드는 쪽에 맡기는 것

- 포트 번호 (고정할지, 시스템이 정하게 할지. Bonjour로 찾으니 고정 안 해도 된다. 나중에 ESP32가 IP+포트로 직접 붙는 단계를 생각하면 고정이 편할 수 있다)
- 맥 서버를 기존 `NWListener`로 할지, macOS 26의 새 `NetworkListener`(WWDC25)로 할지. WebSocket 서버를 지원하는 쪽으로
- 아이패드 쪽 찾기/연결 API (iOS 26 `NetworkBrowser`/`NetworkConnection`이 WebSocket을 지원하면 그걸, 아니면 `NWBrowser` + `NWConnection` 또는 `URLSessionWebSocketTask`)
- 볼륨 조절 방법 (`osascript`의 `set volume output volume` 또는 CoreAudio), 맥에서 다른 경로로 볼륨이 바뀌었을 때 따라갈지
- Alacritty 새 창 + 명령 실행의 정확한 인자 (`open -na Alacritty --args --working-directory … -e /bin/zsh -ic '…; exec zsh'` 같은 형태), 명령 글자 안의 따옴표 처리
- 연결 끊김 시 다시 붙기, 페어링 토큰 저장 위치(기기는 Keychain 권장)
- 아이콘 크기 (아이패드 버튼에 선명하게. 128px PNG 정도), 기기 쪽 아이콘 캐시
- 화면 세부 디자인 (색, 글꼴, 버튼 모양). 목업 B안 배치는 지킬 것
- 아이폰 격자 배치, 아이폰에서 볼륨 슬라이더 위치
- 앱 목록 정렬, 검색

## 7. 검토 후 정한 것 (Claude 판단, 해롤드 확인용)

- **명령 버튼의 "실행했음"이 뜻하는 것:** 맥 앱은 Alacritty 창 안을 볼 수 없고 `blogrun`은 끝나지 않는 명령이다. 그래서 실행 전에 확인할 수 있는 것만 확인한다. 폴더가 있는지, 명령의 첫 단어가 zsh에서 찾아지는지(별칭/함수/명령, `zsh -ic 'whence …'`). 둘 다 통과하고 Alacritty 창이 열리면 "실행했음", 아니면 "실패: 폴더 없음 / blogrun을 못 찾음"처럼 이유와 함께 알려준다. 명령이 창 안에서 성공했는지까지는 알려주지 않는다
- **연결 보안:** 집 와이파이라 암호화(TLS)는 하지 않는다. 대신 페어링 뒤에는 토큰을 네트워크로 다시 보내지 않는다. 맥이 매번 새 무작위 값을 보내고, 기기는 토큰으로 만든 서명(HMAC-SHA256)만 돌려준다. 오간 메시지를 엿봐도 다시 써먹을 수 없다. ESP32도 HMAC-SHA256은 기본 라이브러리(mbedtls)로 할 수 있어서 나중에 같은 방식으로 붙는다. 4장의 `hello`의 `token`은 이 방식으로 바뀐다
- **허락 취소:** 맥 메뉴에 허락한 기기 목록과 "허락 취소"를 둔다. 잃어버리거나 바꾼 기기를 설정 파일을 직접 고치지 않고 지울 수 있게
- 페이지 추가/삭제, 처음 배치(빈 1페이지), 폴더를 안 적었을 때 기본 폴더(홈), 두 기기에서 동시에 고칠 때(나중 것이 이김)는 만드는 쪽이 정한다
